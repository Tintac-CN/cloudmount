## 目标
SCM 服务路径与前台行为一致（placeholder_mount 生效）+ service.rs 死 FFI 入口删除 + `--interval` 烘焙修复 + 坏配置拒绝启动。

## 触及文件
- `crates/cloudmount-daemon/src/main.rs`：
  - **F-12**：`ServiceCommands::Run` 分支（:193-220）按 `cli.placeholder_mount` 分派：true → 新增 `run_service_placeholder_blocking`（SCM 版占位符挂载循环）；false → 既有 `run_service_engine_blocking`。`run_placeholder_mount` 重构抽出主循环 + `stop_check: &dyn Fn() -> bool` 参数（前台 `|| false`；SCM 传 `stop.should_stop() || service::should_exit()`），轮次间与分段 sleep 处检查；停止后走 `control.stop()` + `Arc::try_unwrap` + unmount
  - **F-12 附加**：`build_launch_args`（:294-315）参数向量组装提取为**跨平台纯函数**（纯 Vec<String>，无 windows API；补 `--interval` 无条件烘焙——值即 clap 解析结果含配置默认注入）；windows 执行面留原处
  - **F-13**：:162-165 `load().unwrap_or_else(warn + default)` → `load().context("配置文件加载失败（修正该文件，或删除后重启以恢复默认配置）")?`——fail-fast；错误链含「解析失败」+ 文件路径（沿 load_from 既有消息）；文件缺失走默认值不受影响
- `crates/cloudmount-daemon/src/service.rs`：删除死 FFI 入口（`define_windows_service!(ffi_service_main, service_main)` + 手写解析，约 70 行）+ 对应 `#[allow(dead_code)]`；保留 install/start/stop/uninstall/executor/should_exit（全在用）
