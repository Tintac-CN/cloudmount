# Unit U3: F-11 oss_put 显式失败

> 映射：AC11 / T-19、T-20　依赖：U1（T-24 回环提供 upload() → oss_put 可达性）　泳道 1

## 目标
OSS PUT 非 2xx 必须显式失败（数据丢失防护闸门）：错误类型 `Error::Http{status, body 摘要}`（5xx 进既有轮内重试 is_retryable，4xx 快速失败）。

## 触及文件
- `crates/cloudmount-driver115/src/cookie.rs`：`oss_put`（:619-635）——`send` 后取 `resp.status()`；非 2xx → `Err`（状态行 + 响应体前 2KB 摘要，`io::Read::take(2048)` 限长；OSS XML 错误体不含凭据）
- `crates/cloudmount-driver115/src/error.rs`：如 `Error::Http` 需携带体摘要则扩字段（is_retryable 既有分类不动：Http ≥500 可重试）

## TDD 失败测试（先行提交）
- T-19（红：现状吞状态返回 Ok）：mock OSS 403/500 → 经公开 `upload()` 全链路（T-24 回环后到达）返回 Err、错误含状态码与体摘要、上层不报成功
- T-20：OSS 200 + 合法响应 → Ok；PUT 的 URL（注入基址指向 mock）/Authorization OSS 签名头/UA 断言

## 实现
一行级错误分支；成功路径（2xx + 既有 verify_upload）不变。上传失败从"假成功"变"真失败+重试"属缺陷修复本身（intent 允许的行为变化）。
