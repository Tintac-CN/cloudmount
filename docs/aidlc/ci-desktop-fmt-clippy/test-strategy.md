## 分层策略

- **单元**（字面断言脚本，本地 Git Bash 全可跑；载体=新脚本或扩展 desktop-installers-yaml.test.sh，归 OQ④/prd 定）：TP-01（desktop job id/runs-on/命令唯一字面/缓存值精确匹配/负子项）+ TP-02（既有四 job step 字面锚定集零删改+workflow 级 on/env/matrix+diff 文件集，job_block 界定防跨 job 误配）+ TP-04（脚本自检：防空真/CRLF 剥除/降级计数诚实/断言不得弱化/不破坏既有计数；P0 进门同跑）。**不测**：YAML 语义级有效性、CI runner 实际执行行为、desktop 源码修复（dirty 修复归 desktop 代码批/OQ③ 裁决——本批仅 CI 配置变更）、diff 的代码内容语义审查（diff 文件集只核路径）。
- **集成**（ci.yml 结构+desktop 现状，本机可跑）：TP-05（safe_load 解析粗检+坏 YAML 注入自校验——actionlint 缺失降级沿先例）+ TP-03（本机 cargo fmt/clippy 实测 desktop 现状，带 `RUSTFLAGS="-D warnings"` 复刻 CI，clean/dirty 如实记录——决定 CI 首跑红绿预期）。**不测**：GitHub Actions 三平台 runner 差异、真实缓存命中/体积（TP-06 观察）、CI 时长。
- **E2E**（CI 实跑，不可本地验证——标注归 CI 首跑）：TP-06——PR（`pull_request`）首跑优先/push main 兜底，desktop fmt/clippy step 实际执行+结果与 TP-03 现状一致+缓存命中/体积观察。**不测**：CI 时长优化本身（只观察不设门）；desktop UI 行为（非本批面）；cache 淘汰策略实施（M8 后续批）。

## 缺口与开放问题

- [x] **OQ① 已裁决（2026-10-28 人类）**：形态=独立 `desktop` job + `runs-on: windows-latest` 单腿；TP-01 已落 job id/runs-on 判据。原「rust job 内追加 step」分支作废——TP-02 护栏口径=四既有 job 零删改+新增独立 job。
- [x] **B1 已裁决/落实**：唯一字面源=`cargo fmt --manifest-path apps/desktop/Cargo.toml --all -- --check` 与 `cargo clippy --manifest-path apps/desktop/Cargo.toml --all-targets -- -D warnings`；原 working-directory/cd/--manifest-path 多形态锚选项已删除，并加 `cd apps/desktop`/`working-directory: apps/desktop` 负断言锁定形态。
- [x] **B2/M3 已落实**：rust-cache `workspaces:` 值精确断言 `apps/desktop -> target` + `apps/desktop -> desktop` 负断言（target 相对 workspace 解析，错值使缓存完全失效）。
- [ ] OQ② clippy `--all-targets`：TP-01/TP-03 按终验口径含 `--all-targets` 落字面；若人类收窄须同步修订断言字面（decisions.md 留痕）。
- [ ] OQ③ desktop dirty 处置：预期 clean（dev 互审 fmt 实测 clean exit 0）；dirty=偏差，TP-03 记录明细并触发裁决——修复归本 intent 还是分批不属本测试策略可裁决项。
- [ ] OQ④ 断言脚本载体与文件面：新脚本（架构决策 9 推荐 `scripts/ci-desktop-yaml.test.sh`；prd 草案写 `scripts/ci-yaml.test.sh`）vs 扩展 desktop-installers-yaml.test.sh（既有计数基线变化须如实，该脚本为已完结批锁定绿态）——TP-04 双分支判据随裁决生效，TP-02 diff 白名单脚本名同步。若④裁决「排除」则 AC3 作废，TP-04 与 TP-05 的 AC3 面失去被测对象，映射须回对齐拍重议。
